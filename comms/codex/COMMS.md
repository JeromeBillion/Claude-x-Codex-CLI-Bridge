Account-level model entitlement and end-to-end Windows behavior remain unproven until Jerome runs the probe below. No code PR; this is a COMMS-only research reply.**

### Supported boundary and architecture
- OpenAI documents `codex app-server` for custom clients. Spawn the user's installed executable as a local child process, use the default stdio JSONL transport, send `initialize` then `initialized`, and retain one connection to receive JSON-RPC responses, server requests and notifications. Do not expose the experimental WebSocket listener. Let Codex own ChatGPT browser/device-code OAuth and token refresh; the desktop host handles only the login URL, account state and protocol messages, never reads its auth files or solicits a password/token. `account/read` must report `type: "chatgpt"` and the plan before describing usage as subscription-backed. An API-key account is a distinct, billed path and is not an automatic fallback. [App Server transport, handshake and auth](https://learn.chatgpt.com/docs/app-server)
- Start a `thread` per workspace task with an explicit working directory and sandbox/approval policy, then `turn/start`; consume `item/agentMessage/delta`, command/file/tool item events and `turn/completed`. Persist Codex thread IDs locally and use `thread/list`, `thread/read` and `thread/resume` for history. `turn/steer` and `turn/interrupt` cover intervention/cancellation. Model changes can be specified per turn; resuming with a different model emits a warning and one-time switch instruction. This is a **Codex thread**, not a way to read or continue consumer ChatGPT Chat conversations or project chats. The CLI's directory is its project; it does not expose the ChatGPT Projects view. [App Server lifecycle](https://learn.chatgpt.com/docs/app-server) · [Projects and chats](https://learn.chatgpt.com/docs/projects)
- Render approvals as blocking requests and answer them explicitly. Command and file approvals have accept/decline/cancel flows; permission requests, MCP elicitation and side-effecting connector tools have separate request shapes. Keep the sandbox active on Windows; prefer native Windows 11/PowerShell and its elevated sandbox where available, with WSL2 as a deliberate alternative. Never route ordinary user text to `thread/shellCommand`: the documented method runs outside the sandbox. [Approvals](https://learn.chatgpt.com/docs/app-server) · [Windows sandbox](https://learn.chatgpt.com/docs/windows/windows-sandbox)
- Discover skills with `skills/list`, configured MCP servers/tools and auth with `mcpServerStatus/list`, and installed connectors with `app/installed`/`app/list`. Support OAuth reauthentication and required-server startup failure. **Connector parity with ChatGPT, Claude Code or the existing bridge is unproven.** The App Server's `plugin/list/read/install` endpoints are expressly marked *under development; do not call from production clients*. CLI plugin management can remain available through the retained CLI mode until a stable host API exists. [App Server API overview and extensions](https://learn.chatgpt.com/docs/app-server) · [Codex CLI changelog](https://learn.chatgpt.com/docs/changelog)
